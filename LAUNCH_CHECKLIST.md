# Bluto Box — Launch Checklist

Running notes on what's done and what's left, so nothing gets forgotten if this project is picked back up later.

## ✅ Built and working (tested end-to-end, including live production)

- **Live at https://blutobox-14ks.vercel.app/** — confirmed working end-to-end in production: register, login, upload (real browser test, not just server-to-server), file view/download, all verified 2026-08-01
- Auth: email/password signup, email verification, login, sessions (NextAuth). **Login now requires a verified email** — unverified accounts cannot log in (fixed 2026-08-01, was previously a gap where anyone could register with someone else's email and log in anyway)

- Pro perks: password-protected share links + custom link expiry (Free links are permanent/public)
- Pricing page: feature comparison table (Free vs Pro)

## 💰 Pricing & cost economics research (2026-08-02, not code — for decision-making)

Researched actual current pricing for every service Bluto Box depends on (B2, Cloudflare Bandwidth Alliance, Vercel, Upstash, Neon, Stripe) to answer: is $4.99/mo Pro sustainable long-term, especially if the site gets big? Full sourced breakdown was given in chat — summary here for future reference:

- **Storage is a non-issue.** B2 is $6/TB/mo (~$0.006/GB). Even a Pro user maxing the full 50GB costs ~$0.30/month to store. This will never force a price change on its own.
- **Stripe fees hit the monthly price harder than the yearly one.** 2.9% + $0.30/charge means the $4.99 monthly nets ~$4.55 (~9% fee), while the $39.99 yearly nets ~$38.53 (~3.7% fee, ~$3.21/mo equivalent). The yearly plan isn't just better retention — it's meaningfully better margin.
- **The real risk is download/egress, and it's decoupled from who pays.** Daily download quotas (5GB Free / 25GB Pro / 3GB anon) cap how much *one visitor* can pull, but not how many *different* people download the *same* file. A free or anonymous upload can go viral (e.g. shared in a modding Discord) and cost real money with zero revenue attached — modeled a plausible example: a 5GB file downloaded by 1,000 distinct people costs roughly $50 in B2 egress **plus ~$600 in Vercel bandwidth** (Vercel charges $0.15/GB past the first 1TB/month included in the $20/mo Pro plan, and Free/anon downloads currently proxy through a Vercel Edge Function (`/api/stream`) to enforce the speed throttle + track real usage).
- **Important wrinkle on the planned Cloudflare-fronting-B2 migration**: it will make Pro downloads (which redirect straight to B2) effectively free via the Bandwidth Alliance. **It will NOT help Free/anonymous downloads** — those go through our own edge function first, and Cloudflare's free-egress terms explicitly exclude "compute pulling from storage" paths like that, only genuine CDN passthrough. So the viral-free-file cost exposure above survives the Cloudflare migration as currently architected.
- **Sanity check against pixeldrain** (the reference model for this whole project): pixeldrain does **not** offer unlimited downloads for a flat fee at all — they charge separately per-TB downloaded (€1/TB) on top of storage, precisely because bandwidth is the cost that doesn't scale with a flat subscription. Confirms the concern above is a real, known issue in this exact business category, not hypothetical.

**Recommendation (the "don't want to change the price after getting famous" answer)**: keep $4.99/mo and $39.99/yr stable long-term — storage economics support that forever, no need to hedge Pro pricing against a cost Pro users aren't actually causing. If bandwidth costs ever spike, the adjustable lever should be **Free/anonymous download limits** (tightening the daily quota, or adding a per-file total-bandwidth cap for non-Pro-owned files), not the Pro price — that's normal and non-controversial, unlike raising the price on paying customers. The existing B2 "Caps & Alerts" account limit is already a real emergency brake (uploads/downloads just stop working past that point instead of a surprise bill) — keep it configured and revisit the Free-tier proxy architecture (e.g. a Cloudflare-Workers-based throttle instead of Vercel's edge function) only if real traffic shows the viral-file scenario actually happening, rather than pre-building for a hypothetical.

## 💡 Ideas from competitor research (2026-08-01, not built — for consideration)

Researched pixeldrain, Mega, WeTransfer, and general file-hosting industry practices to see what Bluto Box is missing. Not urgent, just logged so nothing gets lost:

- **Multi-file / batch upload** — drop several files, get one link (or a zip). Biggest functional gap vs. both pixeldrain and WeTransfer; currently Bluto Box is strictly one-file-at-a-time. Likely the most-requested feature once there's real user volume.
- **Some link expiry option for Free tier, not just Pro** — "ephemeral sharing" (links that auto-expire) is becoming the default expectation industry-wide, not just a premium perk. Could offer a few fixed expiry choices (e.g. 24h/7d) to Free users while keeping *custom* arbitrary expiry as the Pro perk, rather than zero expiry control on Free.
- **Lightweight file-type awareness on upload** — right now there's no signal at all about high-risk executable types (.exe/.scr/.bat/etc.) beyond the VirusTotal hash check. A soft warning (not a hard block, which would conflict with being a genuine general-purpose host) could add another layer without hurting legitimate use cases.
- **Filesystem/folder browsing for logged-in users** — pixeldrain's paid tier includes a proper folder view instead of a flat file list. Bigger effort, worth considering once the account page's file list feels cramped.
- **Public API for programmatic upload** — pixeldrain has one; could be a Pro differentiator for power users/developers. Longer-term idea, not urgent.
- **Native apps / browser extension** — Mega has full cross-platform apps. Large effort, not realistic pre-launch; only worth revisiting if the web product gains real traction.
